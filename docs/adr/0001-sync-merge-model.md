# 同步采用服务端权威的任务级合并模型

多设备同步曾以"整份快照后写赢"的备份机制实现，因多设备互相覆盖而重做。最终模型：服务器持有权威活跃数据集（仅任务与图片），客户端推送变更意图（改动的任务记录、删除的任务 id），服务器逐任务按内容哈希判变、后写覆盖，删除移入回收站；其他设备靠本地记录的"上次同步已知集合"（knownIds）感知删除——曾见过而活跃集没有的 id 即已删除。会话、收藏夹、设置现阶段明确留在本地不入池。

## Considered Options

- **全量快照 LWW**（原备份机制）：被否，多设备下后写者整体覆盖先写者，删除无法安全传播。
- **oplog 操作日志**：被否，复杂度与单人多设备场景不成比例。
- **会话 / 收藏夹 / 设置入池**：被否，设置无法逐字段合并（整体 LWW 会静默覆盖 API 配置），会话并发追加需轮次级合并，收益不抵复杂度。协议形状（按类型分节的同步请求）为将来扩池留了路。

## Consequences

- 收藏夹分组不跨设备，但 `isFavorite` 随任务记录同步，收藏标记本身跨设备可见。
- 同一任务两设备并发修改时后同步者赢，先者修改丢失且回收站不兜底（回收站只保护删除）。
